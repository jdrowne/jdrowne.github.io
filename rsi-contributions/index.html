Background

Recursive self-improvement (RSI) is a process in which artificial intelligence (AI) improves its successors. This page proposes small open-source contributions that could advance it.

An AI system can improve at two levels. The first is the harness: the instructions, tools and workflow around a model. The second is the weights: the learned numbers that make up the model itself. The contributions fall into three tracks, each a group of related work: Track A works on the harness, Track B works on the weights, and Track C checks that improvements at either level are real.

Tracks

Track A: Improving HGM

HGM (Huxley–Gödel Machine) is an open-source system in which an AI repeatedly rewrites its own coding harness, and both its code and its evidence have weaknesses. The released code has a bug that corrupts each version's scores and can exhaust memory, though the fix is one line. The paper's wins over other methods come down to one or two problems from a single run of each method, which could be luck. In a simplified simulation, most of HGM's benefit came from testing each version a few problems at a time. The paper's main idea, judging a version by its descendants, helped in only one of six scenarios.

The work here starts by fixing and testing what already exists. The bug and its fix should go to the HGM authors; they are filed on a fork but not yet sent. Next comes the comparison the paper lacks: judging versions by their descendants against judging them by their own scores, with several runs of each. If testing a few problems at a time is what really helps, it should also be tried in OpenEvolve, a similar open-source tool. Publishing every record from one full run would then let others compare methods without rerunning it. This track needs AI model access, Docker to sandbox the AI-written code, and a budget; the HGM authors spent about $5,000 in total.

Track B: Letting AI improve model weights

A recent result shows that AI can improve a model's weights cheaply. In weight-space programming (MIT CSAIL, November 2026), a frontier AI directly edited 0.016% of the weights of a small open model, Qwen3.5-0.8B, with no training and no GPU. The edited model's score on unseen math problems rose from 7.9% to 48.1%, mostly because it stopped repeating itself. The same approach failed on a second model.

Another result takes the more expensive route of training. In Terminal-RSI (October 2026), a 27-billion-parameter open model trained itself on its own verified successes and raised its score on a test of command-line tasks from 51.7% to 86.5%. This needs real training hardware, and the paper doesn't say whether test tasks were kept out of training.

The cheapest place to start is reproducing the editing result, because the edited model and its logs are public and it runs on an ordinary computer. A simple control comes next: checking whether a setting that discourages repetition gives the same gain without editing any weights. If the edit holds up, the method should be tried on another model and another skill. Only once Track C is in place should a model edit a copy of itself, with a person approving each change it keeps and every change logged so it can be undone.

Track C: Checking that improvements are real

Self-improving systems grade themselves, and under pressure they find ways to raise their scores without getting better. The Darwin Gödel Machine, which HGM builds on, was caught doing this. The simulation from Track A shows two further problems. The winning version's score overstated its true quality by 4 to 7 points. A single run also could not reliably tell methods apart: a method truly 5 to 9 points better won only 60% to 74% of single head-to-head runs.

This track turns those lessons into tools. It starts with a one-page checklist covering hidden test problems, repeated runs, a simple baseline to beat, and a grader the system can't change. The checklist should be applied to Tracks A and B first, then turned into a small open-source tool that works with HGM, the Darwin Gödel Machine and OpenEvolve.
